# v0.6

## Ключевые изменения
* **Статическая композиция рантайма:** игры собираются сгенерированными static-хостами без рефлексии — типизированные фабрики сервисов, запуск через собственный launcher-исполняемый файл, бандлы без манифеста. Это режим по умолчанию; динамический рантайм остаётся как opt-in откат. Static-хосты публикуются в NativeAOT.
* **Внешний игровой SDK:** движок распространяется как версионированный MSBuild SDK (`Karpik.Engine.Sdk`): игра живёт в отдельном каталоге, собирается обычными `dotnet restore/build/test/publish`, модули выбираются в `Directory.Build.targets`. Два шаблона: `karpik-game` (минимальная игра) и `karpik-coinrush` (рабочий мультиплеерный семпл CoinRush). Создание проектов — из лаунчера или `dotnet new`.
* **DI через конструктор:** регистрация сервисов — декларативная (`[Export]` + `[ServiceRegistration]`), внедрение — только через конструкторы. Три скопа: `Engine -> ModSet -> Simulation`. Полевое внедрение `[DI]`/`AutoInject` удалено.
* **Контент-пайплайн:** сквозной пайплайн — рантайм-контракты (`AssetRef`/`Lease`, `IContentStore`), `FileContentStore`, версионированный `ContentRegistry` с `TryGet`/`LoadAsync`, Roslyn-кодогенерация `ContentRefs` по `[ContentType]`, таргет-профили (шрифты, шейдеры), упаковка контента под клиент и сервер.
* **Сеть:** сеть была и раньше (RPC-кодогенерация, транспорт LiteNetLib, модули `Network.Shared/Client/Server`). Новое в 0.6 — генерируемый типизированный реестр снапшотов `NetworkSnapshotRegistry` с хешем схемы протокола: клиент и сервер с несовпадающими схемами не соединяются.
* **Редактор:** компактный Unity-like воркспейс — пресеты и сохранение док-раскладок, окно настроек, консоль со структурированными логами и фильтрами, редактирование метаданных ассетов.
* **Логирование и жизненный цикл:** вся диагностика движка переведена на `ILogger` с корректным завершением без потери логов; добавлен асинхронный жизненный цикл систем.

## Статическая композиция и AOT
* Рантайм собирается генератором композиции: контракты, типизированные фабрики сервисов, сгенерированные static-хосты для клиента и сервера. Рефлексивной загрузки модулей в static-хостах нет.
* ECS-реестры (`IEcsUpdateRegistryProvider`) и регистрации сервисов доставляются через статическую композицию; все ECS-системы и кросс-сборочные сервисы должны быть `public`.
* Публикация static-лаунчеров идёт без модульного манифеста (только `Content/`, `Mods/`, нативные зависимости); динамический режим с каноническим манифестом и универсальным раннером — opt-in откат (`KarpikCompositionMode=Dynamic`, иное значение — ошибка `KARPIK010`).
* NativeAOT: публикация self-contained исполняемых файлов (требуется C++ workload), корни для модульных сборок, инстанцирование шаблонов ECS-компонентов, десериализация компонентов без runtime generic instantiation, JSON снапшотов редактора на source-generated сериализации.
* AOT-варнинги: документированный инвентарь подавлений (агрегатные IL2104/IL3053, IL3000/IL3002 от Silk.NET), любой другой trim/AOT warning — ошибка.
* Нативные библиотеки укладываются в выход static-лаунчера; выходы runtime-сборок кэшируются.

## Внешний SDK и шаблоны
* `Karpik.Engine.Sdk`: версионированный MSBuild SDK, валидация игровых проектов (виды `Runtime`/`Test`/`Tool`/`Generator`/`Assets`, стороны `Client`/`Server`/`Shared`/`None`), статические графы проектов, запрет поздних мутаций ссылок, построение runtime-бандлов, интеграция контент-пайплайна.
* Два шаблона в пакете `Karpik.Engine.Templates`: `karpik-game` — минимальная игра, `karpik-coinrush` — рабочий мультиплеерный семпл CoinRush (сервер-авторитетный матч, снапшоты, физика, контент, тесты).
* Создание игры: из лаунчера (выбор шаблона и SDK) или `dotnet new karpik-game --name MyGame --karpik-sdk-version <версия>`; версия SDK фиксируется в `global.json` (`msbuild-sdks`), лаунчер подбирает редактор под SDK игры.
* `MyGame` переведён на шаблон, лаунчеры в корне движка удалены, конфигуратор работает только с движком (без игровых путей).
* Пейлоад движка: дедупликация зависимостей модулей в shared store, вырезанные PDB, хранение 5 последних SDK-установок, полный каталог модулей для сборки SDK.

## Dependency Injection
* DI переведён с полевого внедрения (`[DI]`/`AutoInject`, были с 0.2) на конструкторы. Обычные сервисы регистрируются декларативно — оба атрибута сразу:

```csharp
[Export(typeof(IFoo))]
[ServiceRegistration(ModuleScope.Simulation, ServiceLifetime.Singleton)]
public sealed class Foo(IClock clock) : IFoo { }
```

* Скопы образуют цепочку `Engine -> ModSet -> Simulation`: ребёнок видит сервисы родителя, наоборот — нет. `Singleton` — один инстанс на владеющий скоп, `Transient` — новый на каждое разрешение. Мутабельное состояние симуляции нельзя тащить в родительский скоп ради шаринга.
* `IModuleInstaller.OnRegisterServices` — только для фабрик, готовых инстансов, условных регистраций, сторонних типов и намеренного переопределения атрибутной регистрации (инсталлеры применяются после атрибутов в том же скопе).
* ECS-системы объявляются через `IModule.Add(ISystemRegistry)`, их конструкторные зависимости резолвятся из скопа Simulation. Ручное конструирование зарегистрированных сервисов и service locator для статически известных зависимостей запрещены; `IDisposable` владеет и disposeит Autofac по скопу.
* Для static-хостов регистрации превращаются генератором в типизированные фабрики — без рефлексии в рантайме.

## Редактор
* Unity-like воркспейс: компактная оболочка, пресеты док-раскладок с сохранением (плотность, выбранный пресет, кастомные раскладки), окно настроек.
* Консоль редактора: структурированная история логов, фильтр по уровню (включая Trace), фильтрация runtime-логов.
* Редактирование метаданных ассетов в редакторе.

## Контент-пайплайн
* Рантайм: контракты (`AssetRef`/`Lease`, `IContentStore`, диагностика), `FileContentStore` для loose-файлов с защитой от выхода за корень, `ContentRegistry` с версионированными слотами, `TryGet`/`LoadAsync` и single-flight загрузкой. `AssetRef` — blittable, копирование — zero-alloc.
* Кодогенерация: Roslyn-генератор `ContentRefs` с маппингом `[ContentType]` внутри сборки, `System.Text.Json 8.0.5`, диагностика кодов KCO/KCR.
* Таргет-профили: процессоры шрифтов и шейдеров, упаковка пайплайна под клиент и сервер, CLI метаданных контента, контракт файловой системы в engine core.
* SDK: зависимости модулей дедуплицируются в shared store.
* JSON-экспоненты (включая экстремальные) нормализуются канонически.

## Сеть
* База была и до 0.6: RPC-кодогенерация (`RpcGenerator`, `TargetClientRpcGenerator`), транспорт LiteNetLib, модули `Network.Shared/Client/Server`.
* Новое: генератор снапшотов строит типизированный `NetworkSnapshotRegistry` с `ProtocolSchemaHash` от типов снапшот-компонентов; клиент и сервер настраивают хеш при старте и рвут handshake при несовпадении схем.

## Логирование и жизненный цикл
* Вся диагностика движка (Core-хост, IPC, раннер, воркеры, джобы, сеть) идёт через `ILogger` с указанием места вызова; в редакторе — Trace-фильтр. Завершение процессов дренирует очереди логов — логи не теряются.
* Асинхронный жизненный цикл систем; инициализация сервера идемпотентна на восстановленном мире.
* ECS: десериализация компонентов без runtime generic instantiation.

## Прочее
* `Transform2D` вынесен в новый проект `Spatial2D`; удалён Kveldrid-бэкенд, переход на `NeoVeldrid` NuGet.
* Безопасное освобождение текстурных ресурсов до инициализации графики.
* Threaded-клиент: агрегация таймингов кадров, CPU-время present, асинхронные GPU-тайминги OpenGL; при hot reload сборках неизменные нативные модули пропускаются.

## Заметки по обновлению
* Статическая композиция — режим по умолчанию. Системы и сервисы модулей держите `public`, без скрытых рефлексивных регистраций.
* Новые игры — из шаблонов (`karpik-game`, `karpik-coinrush`); версия SDK фиксируется в `global.json`. Не добавляйте `ProjectReference` на движок вручную.
* Сервисы: `[Export]` + `[ServiceRegistration]`, внедрение только через конструкторы. Состояние симуляции — в скопе Simulation, не выше.
* Состояние, переживающее Hot Reload, держите в ECS-компонентах; рантайм-ресурсы пересоздавайте.
* Контент: используйте `AssetRef`/`Lease` и `IContentStore`; лизы освобождайте.
* `ISystemFixedUpdate` остаётся последовательным; физика и симуляция — на фиксированном dt.
* AOT: новые trim-предупреждения чините, а не подавляйте.
