# Менять активный набор модов без закрытия локального мира

Living ExecPlan по [PLANS.md](PLANS.md). Источник требований — готовый Mnemon-документ «Modding 0.7 — переключение активных модов в игре», `ade5bf4a-17a5-41a6-82b0-d1fa3c783458`, дизайн r20 (managed document r26), D1–D19 и AC1–AC8. Ниже зафиксировано достаточно контракта для работы из репозитория без доступа к хранилищу. Выбор вариантов дизайна не является одобрением этого плана.

## Purpose / Big Picture

Игрок помещает пакет в `Mods/`, обновляет список, меняет выбор и нажимает «Применить». Управляемые одним хостом клиент и сервер применяют выбор вместе в той же Simulation и на том же соединении. Запрещённое переключение оставляет прежний набор и мир. В Debug сервер может скоординировать замену кода/допустимую миграцию схем активных модов и обновить клиентов без переподключения. Release не перечитывает изменённый Lua остающихся модов; Debug reload не добавляет пакеты. Повторное включение создаёт чистую VM, но не отменяет прежних эффектов в мире.

План включает runtime gate, необходимые модовые кодеки/сверку, управляющий API и проверяемый хостовый сценарий. Не включает общий Mod API/JS, каталог, автоматическую доставку или доверие скачанному Lua, полноценный join-admission для модпаков, формат save и его миграции, отключение независимой косметики на выделенном сервере или финальный релизный демо-проход. Уже доступный пакет клиента по-прежнему должен удовлетворять действующей политике разрешений; Debug reload проверяется на заранее подготовленных доверенных пакетах, отсутствие/несовпадение не обходится. Поддержка Release apply в Debug проверяется на общем пути; при подтверждённом техническом конфликте допускается не открывать этот вход в Debug, но не убирать координированный Debug reload.

## Surprises & Discoveries

- Текущий `PollEvents` вызывается в gameplay `Begin`, а удерживаемый client maintenance lease останавливает и очередь worker. Протокол, который ждёт Ready/BaselineApplied через любой из этих путей, зависнет в паузе.
- У текущего `ApplySnapshot` «полный» снапшот всё ещё требует явных ID удалений. CoinRush использует ECS ID как сетевой; это недостаточно для различения инкарнаций. Транспортный ACK не означает, что игровой callback завершился.
- Изначально `RetireRevision` отзывал сразу все query/listeners и общий буфер. Стадии WP-02 используют домены привязок: оставшиеся `opt`/`exc` и host/codec handles блокируют снятие даже пустого пула. Для сменяемого wire codec использовать явный домен того же staged catalog, не raw pool resolver. Защитная проверка Ready не заменяет host quiescence. Параллельный scheduler-кандидат временно поднимает второй набор workers.
- Content уже умеет готовить root, но обычный `PublishBoundary` коммитит независимо, а следующий Begin может сбросить change span. Legacy mod refresh вправе менять cooked-only набор отдельно от стартовой Lua композиции. Поддерживаемый live-хост выбирает basis-driven refresh до открытия admission; менять режим посреди мира нельзя. При несовместимом предыдущем Content root кандидат отклоняется, без импорта чужой истории.

## Real-Time Assessment

- Cold path: чтение, хеширование, компонентные/wire-каталоги, план миграций и Content staging готовятся без живого ECS там, где возможно. Барьер исключает кадры/Jobs, новые аллокации, Lua и I/O **в самой публикации**, а не во всей подготовке или resync. Проверки поколений и размеры ограничены. Не ждать завершения GPU retirement, сетевого gameplay или удерживаемой очереди внутри lease.
- ECS: прежние Dragon ECS пулы и плотные колонки остаются, `inc/exc/opt` разрешаются до каждого нового графа, читаемость bindings сохраняется. Ни поиск по ID, ни блокировки, ни новый refcount на строку/поле. Внешнее CPU/GPU удержание остаётся у Content. Генерация VM, Lua globals/coroutines и запланированные ссылки собственной ревизии живут вместе; неизменные VM и их bindings не пересоздаются; старые токены не оживают.
- Wire: сервер авторитетен. Общая fixed-width метка до schema-specific decode, повторная проверка у deferred dispatch, компактные structs и существующие IReader/IWriter. Обязательные данные и маркеры упорядочены по одному потоку на направление; необязательные replaceable пакеты не становятся обязательными из-за перехода. Не добавлять per-packet allocation, reflection, обход мира или per-frame flush; большой baseline ограничен и передаётся по существующему надёжному транспорту с контролем объёма. Локальный контроль через IPC не заменяет удалённый wire-control. Нет импорта Client в Server/Shared и наоборот.
- Fixed dt, пользовательская пауза и виртуальное время сохраняются; maintenance не наращивает backlog. Warmed common ECS/репликация и Content boundary проверяются отдельно от затрат Lua VM и транспорта, существующих до этой задачи. Измерить drain, quiescence, prepare, commit, retirement, baseline→Resume, сквозное время, peak RAM/VRAM/threads; не объявлять SLA или no-GC для всей Lua VM. Unsafe/второй транспорт/полная копия мира не нужны для первого среза.

## Idempotence and Recovery

- Тестовые пакеты/состояние — временные fixtures, повторный запуск безопасен, пользовательские `Mods/`, `mods.json`, слоты и несвязанные worktrees не трогаются. Один in-flight переход: повтор запроса не создаёт вторую публикацию, устаревший ID не меняет состояние. Abort закрывает только кандидата и высвобождает его reservations.
- До Commit конструктивный отказ сохраняет прежний мир и штатный обмен, включая уже принятую работу. После Commit отказ не откатывает один процесс: fail-stop, диагностика, восстановление — запуск по последней совместимой конфигурации/сохранению средствами хоста, не обещание восстановления несохранённого прогресса. Изменение формата сохранений не нужно для rollback этого PR.
- Изменение scope/контракта или принятого AC возвращает затронутую часть в design review; частные технические правки записываются без повторного согласования. Код после проверки — PR в `codex/modding-0.7`, не в `main`; ветки от незамёрженных задач требуют отдельного разрешения. Планирование само по себе не разрешает push, merge или реализацию.
