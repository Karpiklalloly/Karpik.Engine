## Surprises & Discoveries

- Most of the six historical Network.Codegen assumptions have already been removed. Two RPC dispatcher namespace constants remain; side selection already comes from build properties.
- Clean Static launcher builds evaluated cooked-content wildcards before the referenced Runtime project produced any files (manifest present, zero cooked files instead of eight). Collect runtime Content with execution-time items after project references, for both output and publish.
- Dynamic bundle collection filtered out SDK file references, omitting Karpik.Content.Runtime/Core despite successful compilation. Collect all managed copy-local dependencies; identity-shared engine references remain Private=false. The next real two-project switch starts server and two clients, then exposes a remaining shutdown shadow-tree cleanup failure.
- SDK packing lacked its declared README and never built Core.Codegen for the selected configuration. Restore the required README and include the generator in the existing payload build list; default Release pack succeeds.
- External content compile initially packed with a test-owned NuGet cache but repository-owned intermediates, leaving assets files pointing to a subsequently deleted cache. Reuse the existing owned SDK pack harness; explicitly restore pack-only payload projects in separate evaluations before their build. Restore and build in one MSBuild evaluation is insufficient for fresh netstandard analyzer references.
- `pack --no-build` propagated NoBuild=true into unconditional child Build calls and failed with NETSDK1085. Respect NoBuild on the payload preparation target; the owned harness prepares all payloads before packing. Seed every SDK payload dependency from its current assets file, including SDK-only content packages.
- `dotnet new` consumes a metadata/literal XML Condition as template syntax; use WithMetadataValue in the item expression. Target-time file metadata must come from a separate glob item. Collect only manifest/cooked output so publish does not duplicate the raw Content already provided by project references.
- An inherited installed engine-root override selected a different SDK version in subprocess tests. Clear ambient overrides before applying explicit fixture environment, and select a validated current payload for the acceptance baseline.
- Static state capture stopped the engine loop before IPC StateResponse had been transmitted. Freeze simulation after collection, keep the loop alive, and stop from the existing post-message notification after sending the response. Both server and client loops follow this ordering.
- The current template logs through ILogger and initializes restored ECS worlds idempotently. Update stale log/mutation expectations and inject content-read probes only into owned test games; preserve bundle-relative content assertions and unchanged entity count after restore.
- Waiting for the OS exit event alone can discard trailing redirected logs when the generation is released. Use bounded standard-library Process.WaitForExitAsync to drain streams before successful shutdown completes; caller cancellation remains observable. The final Runner regression passes 138/138 (`runner-final.trx`).
- A later real editor switch reproduced a DLL lock after process exit, callback drain and handle disposal. Keep exit-event cleanup single-pass; final lifecycle cleanup retries only filesystem/access failures with 25/50/100/200/400 ms delays, revalidating ownership on every attempt. A Windows test holding the DLL until 100 ms after handle disposal fails before this change (`transient-shadow-red.trx`); complete Runner passes 139/139 afterwards.
- The next Dynamic run reached hot reload but required a forced kill on ordinary stop. A short real probe confirmed exit code -1, rather than merely missing stdout. IPC shutdown directly changed the shared run flag on the listener thread during a tick. Invoke the shutdown callback through the existing main-thread scheduler, as state capture already does. A thread-identity regression fails before the change (`shutdown-thread-red.trx`); Runner then passes 140/140 and six real startup/state-restart/stop cycles each report two clean exits and zero kills (`shutdown-main-thread-cycle-*`).
- Integration fixtures snapshot repository build outputs to prove isolation. Run their final acceptance without concurrent repository builds; overlapping editor/runner builds invalidate that evidence.
- Desktop smoke verifies first-launch Compact/Unity defaults, center/bottom tab placement, drag/reorder and splitter persistence across restart, Debug/Custom restoration and density persistence. Original workspace and layouts are restored. Full UI runtime/build/publish, backend selection and two-SDK handoff remain open; no firewall permissions were changed.
- Outside the sandbox, editor failures reduce to four stale fixture expectations: two omit the already-supported build configuration arguments and two bypass runtime attribute discovery of `EditorConsoleLoggerModifier`. Corrected these fixtures without changing production logging or process behavior.
- The first editor build encountered Avalonia telemetry writing outside the sandbox. `AVALONIA_TELEMETRY_OPTOUT=1` allows the build to run; full editor baseline then reports 114 passed, 27 failed, eight skipped. Failure details are recorded by the test runner under `artifacts/validation/editor-baseline.trx`.
