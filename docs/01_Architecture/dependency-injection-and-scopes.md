# Dependency Injection и области жизни

KarpikEngine использует Autofac и иерархию областей жизни `Engine -> ModSet -> Simulation`. Обычные сервисы регистрируются атрибутами, сложные регистрации — в инсталлере. Зависимости сервисов и систем передаются через конструктор.

## Регистрация сервисов

Для обычного сервиса укажите экспортируемый контракт, область жизни и lifetime:

```csharp
using System.Composition;
using Karpik.Engine.Core;

public interface IWeatherService { }

[Export(typeof(IWeatherService))]
[ServiceRegistration(ModuleScope.Simulation, ServiceLifetime.Singleton)]
public sealed class WeatherService(IClock clock) : IWeatherService { }

public sealed class WeatherController(IWeatherService weatherService) { }
```

- `[Export]` — стандартный `System.Composition.ExportAttribute`. Он определяет контракт, по которому сервис доступен контейнеру.
- `[ServiceRegistration]` определяет владельца сервиса и lifetime. Без `[Export]` такая регистрация считается ошибочной.
- `Singleton` создаёт один экземпляр на владеющую область. Это не глобальный singleton процесса.
- `Transient` создаёт новый экземпляр при каждом разрешении.
- Тип должен входить в набор сборок, сканируемых композицией Runner.

Field/property injection через `[DI]` для сервисов и систем больше не используется. Не добавляйте `IOnInjectedDI`, ручной `new` зарегистрированных сервисов или service locator для зависимостей, тип которых известен заранее.

Типы ECS-систем модуль объявляет через `IModule.Add(ISystemRegistry)`. Runner создаёт системы в `Simulation` и также передаёт им зависимости через конструктор.

## Когда нужен инсталлер

`IModuleInstaller.OnRegisterServices(ContainerBuilder)` нужен, когда декларативной регистрации недостаточно:

- требуется фабрика или уже созданный экземпляр;
- регистрация зависит от конфигурации или стороны запуска;
- регистрируется сторонний тип, который нельзя разметить атрибутами;
- нужны параметры Autofac, адаптер или декоратор;
- модуль намеренно переопределяет стандартную регистрацию.

```csharp
public sealed class GraphicsModuleInstaller : IModuleInstaller
{
    public string Name => "Graphics";

    public void OnRegisterServices(ContainerBuilder builder)
    {
        builder.Register(context => CreateDevice(context.Resolve<IGraphicsConfig>()))
            .As<IGraphicsDevice>()
            .SingleInstance();
    }
}
```

Внутри одной области атрибутные регистрации применяются раньше явных регистраций инсталлера. Поэтому инсталлер может переопределить их, но такое поведение должно быть осознанным. Не дублируйте одну регистрацию двумя способами без необходимости.

## Иерархия областей

```text
Engine
└── ModSet
    ├── Simulation A
    └── Simulation B
```

Дочерняя область видит экспорты родителей. Родитель не видит сервисы дочерней области. Соседние `Simulation` изолированы друг от друга.

### Engine

Корневая область одного запущенного worker/движка. Здесь живёт инфраструктура, общая для всех наборов модов и симуляций: логирование, менеджер ассетов, конфигурация движка, платформенные и графические сервисы соответствующей стороны запуска.

В `Engine` нельзя помещать изменяемое состояние конкретной игры или симуляции. Область уничтожается последней при остановке worker.

### ModSet

Дочерняя область `Engine` для одного зафиксированного набора загруженных модов и его общей конфигурации. Она содержит сервисы и состояние, которые должны разделять все симуляции этого набора модов, и видит экспорты `Engine`.

Набор модов известен к моменту построения `ModSet`. После построения контейнера моды не добавляют новые регистрации в уже существующий `Engine`. Перед уничтожением `ModSet` сначала уничтожаются все его `Simulation`.

### Simulation

Дочерняя область `ModSet` для одного запущенного экземпляра симуляции. Здесь находятся ECS-миры, игровое состояние, часы симуляции и прочие stateful-сервисы, которые не должны протекать в соседнюю симуляцию.

`Simulation` видит сервисы своего `ModSet` и `Engine`. Она уничтожается первой при остановке, рестарте или смене симуляции. Autofac при уничтожении области вызывает `Dispose`/`DisposeAsync` у принадлежащих ей сервисов.

## Редактор

`Karpik.Editor` собирает отдельный контейнер Autofac при запуске Avalonia. Он сканирует свою сборку и указанные дополнительные сборки. Для редактора используются атрибуты MEF1 из `System.ComponentModel.Composition`: `[Export]` задаёт контракт, `[PartCreationPolicy(CreationPolicy.NonShared)]` создаёт экземпляр на каждое разрешение. `Shared` и `Any` дают один экземпляр на контейнер редактора. Зависимости передаются через конструктор. Это не область `Engine`, `ModSet` или `Simulation` игрового процесса.

Для готовых экземпляров, настроек и фабрик передайте `configure` в `App.CreateEditorContainer`: `builder.RegisterInstance(settings).As<IEditorSettings>()`. Явные регистрации выполняются после экспорта и могут переопределять его; для другого времени жизни также используйте явную регистрацию.

`ViewModelViewHost` получает готовую ViewModel и создаёт только соответствующий View. Для `NonShared` ViewModel разрешайте экземпляр в области жизни владельца экрана; сам `ViewModelViewHost` не управляет её DI-областью или освобождением.

## Правило выбора области

Выбирайте самую узкую область, которая полностью покрывает требуемое совместное использование состояния:

- нужно всем симуляциям и всем наборам модов — `Engine`;
- нужно нескольким симуляциям одного набора модов — `ModSet`;
- относится к одному миру/запуску игрового состояния — `Simulation`.

Зависимости направлены только вниз по цепочке: `Simulation` может зависеть от `ModSet` и `Engine`, `ModSet` — от `Engine`. Обратная зависимость означает ошибочно выбранную область или необходимость вынести контракт/координатор выше без переноса туда изменяемого состояния симуляции.
