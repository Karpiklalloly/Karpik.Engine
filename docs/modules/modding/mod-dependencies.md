# Зависимости модов

Укажите зависимости в `Mods/<папка>/mod_info.json`. Например, мод `weather-ui` требует `weather-core` на обеих сторонах, а на клиенте может использовать `weather-icons`, если тот доступен:

```json
{
  "id": "weather-ui",
  "version": "1.0.0",
  "dependencies": {
    "shared": [{ "id": "weather-core", "minVersion": "2.1.0", "maxVersionExclusive": "3.0.0" }],
    "client": [{ "id": "weather-icons", "optional": true }]
  }
}
```

- `shared` действует и на клиенте, и на сервере; `client` и `server` — только на своей стороне. Группы и весь объект `dependencies` можно опустить, но не заменять на `null`.
- `optional` по умолчанию `false`. Необязательную цель можно не устанавливать. Если она доступна, но не подходит по версии, запуск отклоняется. Установленная папка сама по себе не считается доступной: нужен `Shared/main.lua`, `main.lua` текущей стороны или принятый cooked-пакет этой стороны. Повреждённый пакет без подходящего Lua entry point не считается обычным отсутствием optional-цели.
- Границы сравниваются численно как `MAJOR.MINOR.PATCH`: `minVersion` включительно, `maxVersionExclusive` исключительно. Каждую границу можно опустить. Без обеих границ принимается и произвольная строка версии старого мода. Если одна цель указана в `shared` и в активной группе, действуют обе записи; достаточно одной обязательной записи, чтобы цель была обязательной.
- Сравнение ID точное и учитывает регистр. Самозависимость и повтор цели в одной группе запрещены. Дубликаты ID установленных модов, неверные декларации, неудовлетворённые обязательные зависимости и циклы отклоняют запуск до выполнения Lua и публикации каталога Content. Прежний выбор одной из папок при дубликате ID больше не поддерживается.

Цель загружается раньше зависимого мода; среди модов, которые уже можно загружать, первым идёт меньший ID в ordinal-порядке. Этот порядок используется для Lua lifecycle и [приоритета подмен Content](../../mod-content-overrides.md), но не создаёт рёбер между ECS-системами.

## Lua

`has_dependency(id)` доступна уже в top-level. Передайте ровно одну строку:

```lua
local use_icons = has_dependency("weather-icons")
```

Она возвращает `true` только для разрешённой **прямой** зависимости вызывающего мода на текущей стороне. Чужие, транзитивные, незаявленные и отсутствующие необязательные цели дают `false`. Это не проверка флага enabled и не способ вызвать функции другого мода.

[Перезагрузка Lua-кода](lua-hot-reload.md) использует зафиксированные при запуске порядок и результаты `has_dependency`. Изменения скриптовых деклараций на диске вступают в силу после перезапуска. Обновление модового Content может применить совместимое изменение контентных пакетов без перезапуска, если граф остаётся валиден и не меняются относительный порядок активных Lua-модов или результаты `has_dependency` для них. Отклонённое обновление оставляет предыдущий каталог.
