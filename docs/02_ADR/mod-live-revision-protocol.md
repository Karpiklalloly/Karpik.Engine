# Согласованная смена ревизии модов

Статус: принято, дизайн r20. Проверки и ограничения — [ExecPlan](../../plans/modding-live-set-execplan.md).

## Граница владения

Локальный хост связывает два отдельных worker с точными поколениями через закрытый IPC и проверяет пару игровых peers независимо от адреса. Выделенный сервер координирует только административный Debug reload уже активных модов. Клиентские артефакты должны быть доступны и разрешены локально до исполнения Lua. Хеш подтверждает совместимость, не доверие. Полный допуск новых клиентов, доставка пакетов и disk save не входят.

## Переход

1. Остановить новые заявки, завершить ранее принятые действия и их эффекты на старой ревизии. Доказательство drain выдаёт приложение после обработки и playback, не транспортный ACK.
2. После quiescence подготовить каталоги, scheduler, Content и проекции baseline. Хост ждёт Ready всей фиксированной группы с совместимыми проверенными отпечатками. До Commit отказ оставляет старую ревизию; после решения потеря участника требует fail-stop, не частичного отката.
3. Опубликовать подготовленное под барьером, не ожидая выхода старых Content claims. Сервер отправляет проверяемый полный baseline видимого потока. Клиент сохраняет ECS ID и локальные данные выживших реплик, удаляет только отсутствующие реплики этого потока и проверяет инкарнацию. После применения и очистки прежних очередей клиент подтверждает baseline. Resume идёт первым в обязательном потоке новой ревизии.

LiteNetLib сохраняет прежний формат без opt-in. У согласованных peers обязательные данные и control идут по одному reliable ordered потоку на направление; replaceable не подтверждает drain. Общая метка проверяется до декодирования и при потреблении отложенного события. Во время maintenance прежний transport pump передаётся владельцу барьера; он обрабатывает control вне закрытой gameplay-очереди. Два параллельных pump недопустимы.

Первая проекция Lua объявляется `wire` в Shared-компоненте. Включаются только выбранные скалярные поля фиксированной ширины. Совместимость проверяется до Commit и повторно при приёме baseline; лимиты — 1024 реплики и 64 KiB. Перед Ready сервер проверяет авторитетный набор реплик и бюджет новых строк, включая максимальный размер подготовленной C#/Lua-проекции. Если во время Prepare наблюдается потеря игрового peer, worker отзывает Ready через IPC, даже если IPC ещё жив. Хост должен отклонить операцию без доказанных drain, projection и безопасной границы применения. Примеры проверены [headless-тестом](../../tests/Karpik.Engine.Core.Runner.Tests/ModLiveTransitionEndToEndTests.cs).

### Совместимость API

Старые пиры не участвуют в переходе, но прежний стартовый handshake не заменён. Прямые LiteNetLib `Manager`/`Peer`/`Request` закрыты, чтобы они не обходили gate; обращаться через `INetworkManager`, `IPeer` и `IConnectionRequest`. `AcceptIfKey` возвращает nullable peer — проверяйте результат.
