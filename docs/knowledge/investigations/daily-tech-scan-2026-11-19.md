## 🔧 Новые технологии / фичи

- **[Dawn/Tint: матрицы bf16 в подгруппах Metal](https://dawn.googlesource.com/dawn/+/476cd38f)** — изменение вошло в [ночную сборку Dawn](https://github.com/google/dawn/releases/tag/v20261118.135545), опубликованную 19 ноября в 08:10 UTC.
  - **Что делает:** добавляет bf16 в операции subgroup matrix через WGSL/Tint на Metal. Это возможность реализации Dawn, не гарантия поддержки в браузерах.
  - **Как обходились:** использовали f16/f32 в переносимом шейдере или писали отдельный Metal-код.
  - **Почему пригодится:** новый вариант для матричных GPU-вычислений в Client. Сложность высокая: нужны проверка поддержки, запасной путь и замеры точности и GPU-времени; типичный рендер сам по себе не ускорится. [Лицензия](https://dawn.googlesource.com/dawn/+/095e430d29d7dc15e8b8f738773590b3c4fac33c/LICENSE): BSD-3-Clause, отдельные файлы Apache-2.0; зависимости проверять отдельно.
  - **Этап:** только при необходимости. **Relevance score: Low** — пока нет подтверждённой матричной нагрузки, ради которой стоит поддерживать отдельный путь. **Suggested next step:** `monitor`.

- **[IETF 127: QUIC — qlog и метки времени приёма](https://datatracker.ietf.org/doc/agenda-127-quic/04/)** — повестка 18 ноября, 17:00 UTC; обсуждение черновиков, не новый RFC или релиз.
  - **Что делает:** qlog описывает формат событий транспорта, а предложение receive timestamps — передачу меток времени приёма пакетов.
  - **Как обходились:** локальные таймстемпы, счётчики RTT/потерь и логи на обоих концах.
  - **Почему пригодится:** при пилоте QUIC упростит разбор всплесков задержки Client/Server без смены RPC в Shared. Сбор диагностики вне сетевого hot path; стоимость мала при готовом qlog в стеке, но высокая при смене транспорта ради одной диагностики. Документы IETF не добавляют зависимость; лицензию реализации проверять отдельно.
  - **Этап:** продвинутый этап. **Relevance score: Medium** — это полезно для диагностики, если QUIC уже выбран для эксперимента. **Suggested next step:** `monitor`.

## 🏗 Новые движки / нововведения в старых

- **[Unity 6.6.10f1: отсечение света и граница hot reload](https://unity.com/releases/editor/whats-new/6000.6.10f1)** — 19 ноября, 10:46 UTC.
  - **Что делает:** Forward+/Deferred+ исключают из экранных областей свет и пробы, затрагивающие их только за границами отсечения камеры. Патч также устраняет зависание при domain reload из-за зависимости новой фоновой задачи от старой.
  - **Как обходились:** более грубое отсечение, которое оставляло лишних кандидатов; полный перезапуск вместо повторной перезагрузки при зависании.
  - **Почему пригодится:** для Client точное отсечение стоит проверять только при измеренном избытке кандидатов; реализация средней сложности из-за граничных случаев. Для KarpikEngine дешевле и полезнее регрессионный сценарий повторного hot reload с незавершённой фоновой работой и проверкой сохранности состояния Dragon ECS. Unity проприетарна; заимствовать сценарий, не код.
  - **Этап:** ранний прототип для теста reload, продвинутый этап для рендера. **Relevance score: Medium** — сбой на границе поколений задач применим к hot reload, но не подтверждён в KarpikEngine. **Suggested next step:** `prototype` — воспроизвести сценарий в собственном тесте жизненного цикла.

- **[Unity 6.7 beta 10: владение объектами при восстановлении 2D-физики](https://unity.com/releases/editor/beta/6000.7.0b10)** — 19 ноября, 10:59 UTC.
  - **Что делает:** `ApplySnapshot`, `Create` и `Clone` получили вариант `removeOwned`: он удаляет принадлежащие целевому миру тела, формы, цепочки и суставы, вместо того чтобы отклонять снимок.
  - **Как обходились:** освобождали объекты перед восстановлением или пересоздавали мир.
  - **Почему пригодится:** пример явной политики владения для снимков физического мира — потенциально для отката на фиксированном тике или hot reload. Стоимость полноценного отката высокая; API не гарантирует детерминизм, отсутствие аллокаций или сохранность внешних идентификаторов. Unity проприетарна; использовать как ориентир.
  - **Этап:** только при необходимости. **Relevance score: Medium** — полезно при появлении физического rollback, но не заменяет снимки Dragon ECS и сетевой протокол. **Suggested next step:** `monitor`.
