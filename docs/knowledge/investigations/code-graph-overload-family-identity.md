# Legacy overload families в графе кода

При обновлении графа четыре старые callable-записи не сопоставлялись одному объявлению: конструкторы `IpcClient` и `ProcessManager`, а также `HotReloadAsync` и `WaitForExitAsync`. Их диапазоны охватывали целые группы перегрузок. Выбор одной перегрузки по summary или номеру строки выдумал бы идентичность.

Для такой миграции требуется доказательство по AST обеих ревизий:

- Один однозначный declaring type с namespace и вложенными владельцами.
- Полный набор минимум двух перегрузок с уникальными сигнатурами; набор совпадает между ревизиями.
- Диапазон каждой aggregate-записи точно охватывает всю группу в своей ревизии.
- ID и имя сохранены; class containment, если присутствует, соответствует исходникам.

Тело метода может измениться при сохранении сигнатур. Нельзя принимать потерю/изменение перегрузки, смену владельца, неполный диапазон, неоднозначный class, conditional/partial declarations или ошибку парсинга. Не использовать такую проверку для подтверждения удаления символа.

Для данного случая временная проверка поддерживала только named C# classes с concrete method/constructor bodies и сравнивала точные токены сигнатур. Это консервативная миграция, а не универсальное определение эквивалентности C# типов.

Все четыре реальные группы прошли проверку; 17 отрицательных случаев сохранили отказ. После строгих merge/save gates в графе появились явные class owners. Исходный helper восстановлен; постоянное расширение инструмента не устанавливалось.

См. [ExecPlan с результатами миграции](../../../plans/0.6-tail-acceptance-execplan.md). Граф и документация описывают структуру; поведение runtime подтверждается исходниками и тестами.
