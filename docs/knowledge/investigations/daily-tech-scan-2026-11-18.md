## 🔧 Новые технологии / фичи

### [Dawn — асинхронное создание шейдеров D3D11](https://dawn.googlesource.com/dawn/+/687bd3b2d28669ebfe7e82d6e321681b0ef77b57) · 18 ноября, 05:06 UTC
- **Что делает:** создаёт объекты шейдеров параллельно записи команд; ждёт при submit. С debug layer остаётся синхронный путь. Это изменение реализации WebGPU, не спецификации.
- **Как обходились:** шейдеры требовались уже при записи; типичный обход — прогрев при загрузке.
- **Почему полезно:** референс для hot-reload шейдеров в Client. Сложность средняя: ожидание может лишь переехать в submit. Измерять p99 записи и submit отдельно. Узкое место у нас не подтверждено. [BSD-3-Clause](https://dawn.googlesource.com/dawn/+/687bd3b2d28669ebfe7e82d6e321681b0ef77b57/LICENSE).
- **Этап:** только при необходимости. **Relevance score: Medium** — полезно, если профилировщик покажет пики при пересоздании шейдеров. **Suggested next step: monitor**.

### [Mozilla Neqo 0.36.0](https://github.com/mozilla/neqo/releases/tag/v0.36.0) · 18 ноября, 09:59 UTC
- **Что делает:** учитывает лимит UDP payload удалённой стороны для обычных QUIC-датаграмм и не наращивает congestion window в фазе избегания перегрузки без новых подтверждённых байтов.
- **Как обходились:** ограничивали размер снапшотов консервативным бюджетом; congestion control оставался свойством транспорта.
- **Почему полезно:** сценарий для тестов доставки снапшотов Client/Server без изменения RPC-контрактов Shared. Тесты дёшевы; миграция на Rust-транспорт и interop дороги, выигрыш не доказан. Код Neqo — [MIT или Apache-2.0](https://github.com/mozilla/neqo/blob/v0.36.0/Cargo.toml); зависимости проверяются отдельно.
- **Этап:** продвинутый, только если выбран QUIC. **Relevance score: Low** — полезный тестовый сценарий, но не повод менять транспорт. **Suggested next step: monitor**.

### [NuGet.org — отложенная публикация](https://devblogs.microsoft.com/dotnet/nuget-staged-publishing/) · 17 ноября, 21:00 UTC
- **Что делает:** валидирует загруженные пакеты приватно; сопровождающий отдельно публикует пакет или группу. Группа не атомарна; приватного restore нет.
- **Как обходились:** проверяли в локальном или частном фиде, затем публиковали на NuGet.org. Для тестового restore частный фид всё ещё нужен.
- **Почему полезно:** дешёвый способ проверить состав согласованного выпуска пакетов Shared и SDK модов до публикации. Выигрыш в процессе выпуска, не в runtime. Функция сервиса, лицензии пакетов не меняются.
- **Этап:** только при необходимости. **Relevance score: Medium** — пригодится при первом выпуске нескольких зависимых публичных пакетов. **Suggested next step: monitor**.
