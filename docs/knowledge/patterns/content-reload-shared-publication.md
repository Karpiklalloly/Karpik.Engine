# Один координатор для обновлений двух слоёв Content

Два независимых подготовителя легко перезаписывают изменения друг друга, если строят кандидатов от одного старого снимка. Сериализуйте базовый reload и refresh модов одним координатором. Запрос берёт неизменяемый им слой из последнего опубликованного снимка, когда начинается подготовка, а не когда запрос поставили в очередь.

Держите ограниченную очередь: новый запрос базы вытесняет только прежний ожидающий запрос базы и становится в хвост; повторный ожидающий или подготавливаемый refresh модов получает `Busy`. Вычисляйте изменения итоговых ID заранее. На границе кадра только публикуйте готовый снимок и подготовленные уведомления, без файловых операций, блокировок и аллокаций.

`Applied` подтверждает смену снимка, а не освобождение старых ресурсов. Следующее обновление не начинает подготовку до завершения освобождения предыдущего снимка. Проверяйте обе очередности, вытеснение запроса базы при ожидающем refresh и остановку до границы публикации.
