# Завершение worker через главный поток

IPC listener не должен менять состояние игрового цикла посреди tick. Это может оставить worker работающим после ShutdownAck и привести к принудительному завершению процесса.

В `IpcClient` сначала отправляется ShutdownAck, затем callback остановки выполняется через существующий `MainThreadScheduler.InvokeAsync`. Если scheduler не установлен, сохраняется прямой вызов. Scheduler должен продолжать обслуживать очередь до выполнения callback; подтверждение IPC само по себе не доказывает завершение процесса.

Для state capture порядок отдельный: заморозить симуляцию, отправить StateResponse и только после отправки остановить цикл. Получение снимка не должно прерывать передачу ответа.

Проверять нужно поток выполнения callback и фактический выход процесса, а не только наличие сообщения об остановке. Регрессия `ShutdownRequest_UsesTheMainThreadScheduler` воспроизводила неправильный поток до исправления; после него Runner прошёл 140/140, а шесть реальных циклов дали по два чистых выхода без forced kill.
