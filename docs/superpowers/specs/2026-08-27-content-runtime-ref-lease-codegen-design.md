# Content Runtime: Slot Registry + AssetRef/Lease + Codegen (B slice)

> Date: 2026-08-27
> Status: draft (pending user review)
> Branch: content-pipeline
> Related: `docs/02_ADR/content-pipeline-build-contract.md` (accepted), `docs/04_Roadmap/kanban-content-pipeline-approach-2.md` (Runtime registry), `plans/content-pipeline-foundation-execplan.md` (done), `Karpik.Content.Core/*`

## 1. Purpose

Provide a reproducible runtime that loads cooked artifacts without knowing source paths. Build (`Karpik.Content.Core`/`Tool`) produces `manifest.json` + `artifacts/ab/cd/<hash>.cooked`. Runtime reads the manifest through an opaque `IContentStore`, exposes stable typed handles `AssetRef<T>` (copyable, no ownership) and `AssetLease<T>` (single owner), and generates those handles from the manifest at compile time so paths/GUIDs are not hand-written. `AssetsManager` stays untouched in this slice; both systems coexist.

Success for slice B (validated):
- `FileContentStore` (loose files) + `ContentRegistry` with slots (`state/version/payload/dependencies`) and `single-flight` load.
- `AssetRef<T>` copy is zero-alloc, `TryGet`/`Lease` is lock-free on read, `LoadAsync` is single-flight, `version` is present for future hot reload.
- Codegen `ContentRefs.g.cs` is generated in the consumer's assembly (where the payload type is declared) via `[ContentType]` mapping, contains one `AssetRef<T>` per `logicalName` plus `const string` paths, sorted by `AssetId`, byte-identical for identical manifest.
- Tests: unit (slot/state/version, single-flight, missing/failed, Lease version mismatch), golden cooked, allocation (100k copies of `AssetRef`), store/manifest, codegen snapshot, `TemporaryDirectory` helpers — all green, no `File.Open` in `Update`/`ECS` hot paths.

## 2. Architecture & Module Boundaries

- `Karpik.Content.Core` (existing, build-time only) — no runtime change.
- **New `Karpik.Content.Runtime`** (`Shared`, `net10.0`, no `Veldrid`/`Autofac`/`AssetsManager`):
  - `ContentManifest` reuse (read-only `LoadFromFile`, `Parse`), no write.
  - `IContentStore : ReadOnlyMemory<byte> Get(ArtifactLocator); Task<ReadOnlyMemory<byte>> GetAsync(...)` — first impl `FileContentStore : IContentStore` (in `Shared` neutral, but `Client`/`Server` bootstrap creates it with `outputRoot`; `Shared` never calls `File.Open` directly in hot path).
  - Slot: `ContentSlot<TPayload> { AssetId Id; SlotState State; uint Version; TPayload? Payload; AssetId[] Dependencies; Task? Inflight; object Sync; }` — dense `Dictionary<AssetId, Slot>` keyed by `AssetId`, built from `RegisterManifest` sorted by `AssetId`.
  - Handles: `readonly struct AssetRef<T> : IEquatable<AssetRef<T>>, IComparable<AssetRef<T>>, IEcsComponent` — fields `Guid _guid` + `uint _version` + `int _typeId` (20-24 bytes), `IsAlive(ContentRegistry)` checks `slot.Version`, copy is `memcpy`, no heap. `readonly ref struct AssetLease<T>` (stack-only, `Dispose` pattern without `IDisposable` boxing) — only one owner (`using var lease = registry.Lease<T>(ref)`), `TryGet<T>(AssetRef<T>, out AssetLease<T>)` is zero-alloc.
  - `ContentRegistry` — `RegisterManifest(manifest, store)`, `TryGet<T>(AssetRef<T>, out Lease<T>)`, `LoadAsync<T>(AssetRef<T>) : Task<Lease<T>>`, `bool IsLoaded(AssetRef)`, thread-safe per slot (`lock(Slot.Sync)` on write, `Volatile.Read` on read).
  - No `Client` graphics/input refs; `Client` only provides `FileContentStore` instance and a hook for future backend upload phase (stub).
- **New `Karpik.Content.Codegen`** (`netstandard2.0`, `IsRoslynComponent:true`):
  - `IIncrementalGenerator`, `AdditionalFiles: **/*.json.meta` + `AnalyzerConfigOptions: KarpikContentManifest` (`<KarpikContentManifest>path/to/manifest.json</>`).
  - Reads manifest if present (primary), fallback to `.meta` scan with `KCO301` warning (`manifest not built yet`).
  - For each `entry` (sorted by `AssetId`) emits `ContentRefs.g.cs` in the **consumer's compilation** (where the payload types live), so `typeof(HeroConfig)` resolves without `object` fallback.
  - Mapping `declaredType -> CLR type` via `[ContentType("raw-json")]` placed on the payload type in the same assembly: generator collects `GetDeclaredTypesWithAttribute<ContentTypeAttribute>()` → `Dictionary<string, INamedTypeSymbol>`. `entry.declaredType` lookup → `AssetRef<FoundType>`, else `AssetRef<RawJsonPayload>` + `KCO304` warning.
  - Output `obj/<cfg>/generated/Karpik.Content.Codegen/ContentRefs.g.cs` (`<auto-generated/>`), incremental cache by `AdditionalFiles` hash + `AnalyzerConfigOptions`.
- **Sdk wiring:** `Karpik.Engine.Sdk` sets `KarpikContentOutput` (`$(IntermediateOutputPath)Content\`) and `KarpikContentManifest` property, `Directory.Build.props` adds `ProjectReference(Analyzer)` for `Karpik.Content.Codegen` (as `Network.Codegen`).

Real-time: `AssetRef` copy is 2 `long` + `int`, no heap; `TryGet`/`Lease` lock-free read.

## 3. Data Flow & Lifecycle

1. **Init:** `var store = new FileContentStore(outputRoot); var manifest = ContentManifest.LoadFromFile(manifestPath); registry.RegisterManifest(manifest, store)` — builds slots `Unloaded`, validates `UnknownDependency` etc. (re-check of `effective manifest`; duplicates already caught at build).
2. **Load:** `registry.LoadAsync<T>(ref)` — fast path: if `State==Loaded && Version==ref.Version` → `Lease` immediate, no alloc, `Volatile.Read`. If `Loading` → return same `Task` (single-flight). Else `State=Loading`, start `store.GetAsync(locator)` (+ `RawJson` canonical decode) on `Task.Run` (future `JobSystem`), `await` outside `Update`. On success: `slot.Payload = T`, `State=Loaded`, `Version++`, complete `Task`, distribute `Lease` to awaiters. On missing locator: `State=Failed`, `KCR201`, `Task` faulted.
3. **Lease:** `using var lease = registry.Lease<T>(ref)` (`TryGet` without alloc). `Lease` holds `ref Slot` + snapshot `Version`; `Dispose` does not free payload (payload lives in slot; `Lease` only proves liveness). `ref.IsAlive(lease)` → `slot.Version == lease.Version`.
4. **Errors:** `TryGet` returns `false` + `Failed` state, no exception in hot path; `LoadAsync` after `Failed` creates new `Task` (not cached failure); `store` missing → `Failed` + diagnostic.

## 4. Codegen Contract (All Resources/Paths)

- **Input:** `KarpikContentManifest` (`manifest.json` path) primary; fallback `**/*.json.meta`. Entries sorted by `AssetId` (`CanonicalJson` order).
- **Output `ContentRefs.g.cs`:**
  ```csharp
  public static partial class ContentRefs {
      public static readonly AssetRef<RawJsonPayload> Game_A = new ("16755701-7b8a-4dfe-ad91-b5a28ba28882", "game/a", 1);
      public static readonly AssetRef<HeroConfig> Game_Player_Hero = new ("...", "game/player/hero", 1);
      public const string Game_A_Path = "game/a";
      public const string Game_Player_Hero_Path = "game/player/hero";
      public static readonly AssetRef[] All = { Game_A, Game_Player_Hero };
      public static readonly IReadOnlyDictionary<string, AssetRef> ByPath = ...;
  }
  ```
  Name: `LogicalName` → `PascalCase` (`game/player/hero` → `Game_Player_Hero`), collision → `_2`. `All`/`ByPath` sorted by `AssetId`. No `DateTime`/absolute paths.
- **In-assembly generation:** generator runs in consumer's compilation, so `AssetRef<HeroConfig>` where `HeroConfig` is declared in `MyGame.Shared` is visible via `compilation.GetTypeByMetadataName` or attribute scan, no `object` fallback. Fallback `AssetRef<RawJsonPayload>` + `KCO304` only if `[ContentType]` missing.
- **Optional `partial` per type:**
  ```csharp
  [ContentAsset("game/player/hero")]
  public sealed partial class HeroConfig { } // generator: partial HeroConfig { public static AssetRef<HeroConfig> Ref => ContentRefs.Game_Player_Hero; }
  ```
- **Errors:** duplicate `logicalName` already `KCO005` at build, but codegen re-emits `KCO302` if seen in fallback; invalid `logicalName` → `KCO303`; missing manifest → `KCO301` warning, not error.

## 5. Diagnostics, Errors, Testing

- **Codes:** reuse `KCO001..KCO019` + runtime `KCR201 StoreMissingArtifact`, `KCR202 SlotFailed`, `KCR203 UnknownManifestId`, `KCR204 LeaseVersionMismatch`, `KCO301 ManifestNotBuiltUsingMetaScan`, `KCO304 NoContentTypeAttributeFallback`. `ContentDiagnostic(Code, Severity, RelativePath, Message)` sorted `Ordinal`, no absolute paths.
- **Error handling:** `TryGet`/`Lease` no throw in hot path; `LoadAsync` single-flight caches success, failure is retryable; `FileContentStore` missing → `Failed` state.
- **Real-time invariants:** `AssetRef` copy 100k → 0 allocations (`Benchmark`), `TryGet` lock-free read, CPU I/O outside `Update`/`ECS`/`merge` (helper `AssertNoFileIoInUpdate`).
- **Tests (in `Karpik.Content.Runtime.Tests`):**
  - Unit: `AssetRefIsAlive`, `LeaseVersionMismatch`, `SlotStateTransition`, `SingleFlightTwoConcurrentLoadsOneStoreGet`, `MissingArtifactFailed`, `DuplicateLoadReturnsSameTask`.
  - Golden: `RawJson` canonical cooked, `FileContentStore` manifest+artifact read.
  - Codegen: snapshot `ContentRefs.g.cs` for fixed manifest (deterministic order), `NoFallbackWhenContentTypePresent`, `WarningWhenNoAttribute`.
  - Helpers: `TemporaryDirectory` (as in `Karpik.Content.Tests`), `ContentRegistryTests`, `FileContentStoreTests`.
  - Allocation: `AssetRef` copy benchmark.

## 6. Build, SDK & Deployment

- **Projects:** `Karpik.Content.Runtime` (`Shared`, `net10.0`), `Karpik.Content.Codegen` (`netstandard2.0`, `IsRoslynComponent`), `Karpik.Content.Runtime.Tests`. `Core` stays build-only.
- **Sdk order:** `content build` before `CoreCompile` (`BeforeCompile` target in `Karpik.Engine.Sdk`), manifest → generator reads `KarpikContentManifest` property + `AdditionalFiles`, incremental hash cache, no rewrite when byte-identical.
- **CI/Idempotence:** `validate`/`list`/`why` read-only; `build` idempotent (manifest byte-identical → no rewrite). `FileContentStore` loose files first; future `pack` only changes `IContentStore`, not `AssetRef`/`manifest`.
- **Migration:** `AssetsManager` coexists; no `Client`/`Server` hot path change in this slice. 2D sample migration of `TextureLoader`/`FontLoader` to `AssetRef` is next slice.
- **Future:** `IContentStore` can be replaced with `Pack/Mmap/Chunk` without changing `AssetRef<T>` or manifest entries; `version` already enables hot reload.

## 7. Open Questions Resolved

- `AssetRef` is `IEcsComponent` `readonly struct` (ECS-compatible), `AssetLease` is `readonly ref struct` (stack-only, `Dispose` pattern) single owner.
- `single-flight` and `version` are included now (not deferred) per user B choice.
- All resources/paths are codegen'd (central `ContentRefs` + `const string` paths; per-type `Ref` optional via `[ContentAsset]`).
